# Translations

English under `content/en/` is the sole source of truth.

Translations are stored in this repository and are **not generated by GitHub Actions**. This keeps publishing and PDF export free of paid translation APIs and makes every multilingual edition reproducible from a Git commit.

## Workflow

Each deployed locale has a directory under `translations/<locale>/` that mirrors the Markdown paths under `content/en/`.

When English changes:

1. Claude Code (or another explicitly chosen translation tool used during editing) checks which translated pages are missing or stale.
2. Only those pages are translated/updated.
3. The translated Markdown is committed together with the English change.
4. GitHub Actions validates that every required translation is current.
5. GitHub Actions builds/deploys the website and PDF exports from the committed files only.

GitHub Actions performs **no translation API call** and requires no `OPENAI_API_KEY` or other paid translation credential.

## Source-hash rule

Every committed translation must include YAML front matter with a `source_hash` produced by `scripts/multilingual_site.py` for that locale and English source revision. The builder compares this value with the current English source and glossary. A missing or mismatched hash marks the translation as missing/stale.

Production builds use strict mode (`--require-translations`). If any required translation is missing or stale, publication stops instead of silently publishing English text under a non-English locale.

## Current deployment locales

Active for this phase (`deploy: true` in `localization/locales.yml`, and therefore required by `--require-translations`):

- Italian (`it`)
- Simplified Chinese (`zh-Hans`)

Other locale codes remain defined in `localization/locales.yml` with `deploy: false` for future re-activation, but are intentionally out of scope for now and are not built, validated, or translated.

## Rules

- Meaning changes must first be approved in English.
- Translations must not introduce new technical or commercial claims.
- Preserve Markdown structure, links, image paths, formulas, steel grades, product names and HRC values.
- Only missing/stale pages should be regenerated after an English change.
- Japanese, Simplified Chinese and Traditional Chinese deserve terminology review by a competent speaker familiar with kitchen knives.
- Human corrections may be made directly to committed translations, but when the English source changes the translation must be reviewed again and its source hash refreshed.

The deployment configuration is defined in `localization/locales.yml`, and the builder/validator is `scripts/multilingual_site.py`.
